## 1. Обзор проекта (Overview)

**RediForge** — это масштабируемое in-memory хранилище данных корпоративного уровня, разработанное с нуля на основе фундаментальных системных принципов. Движок базы данных **не имеет внешних runtime-зависимостей** и обеспечивает **100% совместимость с бинарным протоколом Redis RESP2 (REdis Serialization Protocol)** на уровне сокетов TCP. Это делает RediForge прозрачной прямой заменой для стандартных клиентов Redis: `redis-cli`, `ioredis`, `redis-py`, `Jedis`, `go-redis`.

В систему интегрирована **реактивная веб-панель администрирования**, работающая через высокоскоростной WebSocket-мост. Панель обеспечивает визуализацию телеметрии в реальном времени, динамический график расхода оперативной памяти, инспектор пространства ключей с расчетом TTL, разграничение прав доступа (RBAC) и полнофункциональный интерактивный CLI-терминал в браузере.

## 2. Архитектура системы (Architecture)

```
                 +---------------------------------------+
                 |            Клиентский уровень         |
                 |  (redis-cli / ioredis / Веб-браузер)  |
                 +---------------------------------------+
                               |                 |
                   Стандартный TCP 6379     WebSocket / HTTP 8080
                               |                 |
                 +--------------------+   +-----------------------+
                 |   Парсер RESP2     |   |    Мост HTTP / WS     |
                 | (Конечный автомат) |   | (SSRF-файрвол и CORS) |
                 +--------------------+   +-----------------------+
                               \                 /
                            +-----------------------+
                            |     Шлюз команд       |
                            | - Ограничитель частоты|
                            | - Аутентификация RBAC |
                            | - Блокировка опасных  |
                            | - Аудит с маскировкой |
                            +-----------------------+
                                        |
                            +-----------------------+
                            |     Реестр команд     |
                            |  (102 команды RESP2)  |
                            +-----------------------+
                                        |
     +----------------------------------+----------------------------------+
     |                                  |                                  |
+-------------------+            +-------------------+            +-------------------+
| Хранилище Multi-DB|            |   Брокер Pub/Sub  |            |   Персистентность |
| (16 баз данных)   |            | (Каналы и шаблоны)|            | (RDB и логи AOF)  |
| - Вытеснение LRU  |            +-------------------+            +-------------------+
| - Очистка TTL     |
+-------------------+
```

### Ключевые технические возможности:
1. **Детерминированный парсер потока RESP2**: Обработка сетевых буферов по технологии zero-copy без промежуточных строковых аллокаций. Поддерживает простые строки (`+`), ошибки (`-`), целые числа (`:`), bulk-строки (`$`) и массивы (`*`).
2. **Структуры данных и вычислительная сложность**:
   - **Strings** ($\mathcal{O}(1)$): Бинарно-безопасные байтовые строки, 64-битная атомарная целочисленная арифметика (`INCRBY`, `DECRBY`), битовые операции (`BITOP`, `BITCOUNT`).
   - **Hashes** ($\mathcal{O}(1)$): Ассоциативные массивы «поле-значение» с пакетными операциями (`HMSET`, `HMGET`).
   - **Lists** ($\mathcal{O}(1)$): Двусвязные деки с операциями push/pop на обоих концах (`LPUSH`, `RPOP`, `RPOPLPUSH`).
   - **Sets** ($\mathcal{O}(1)$): Множества уникальных строк с поддержкой объединения, пересечения и разности (`SUNIONSTORE`, `SINTERSTORE`, `SDIFFSTORE`).
   - **Sorted Sets (ZSets)** ($\mathcal{O}(\log N)$): Сбалансированные массивы с хэш-индексом скоров для мгновенного расчета рангов (`ZRANK`) и выборки диапазонов (`ZRANGEBYSCORE`).
3. **Двойная подсистема персистентности**:
   - **RDB-снимки**: Периодическая атомарная бинарная сериализация в файл `dump.rdb` с сохранением опкодов баз данных, меток TTL и контрольных сумм CRC64.
   - **AOF (Append-Only File)**: Упреждающая запись транзакций (WAL) с политиками сброса на диск (`always`, `everysec`, `no`) и фоновой компактизацией (`BGREWRITEAOF`).
4. **Учет памяти и алгоритмы вытеснения LRU**:
   - Точный побайтовый учет занятой оперативной памяти во всех 16 базах данных.
   - Политики вытеснения `allkeys-lru`, `volatile-lru` и `noeviction` гарантируют отсутствие падений из-за Out-Of-Memory (OOM).
5. **Двухфазная модель истечения TTL**:
   - Пассивная проверка: при каждом обращении к ключу.
   - Активная вероятностная выборка: фоновый таймер каждые 100 мс опрашивает по 20 случайных ключей в каждой БД.
6. **Безопасность Zero-Trust и защита от SSRF**:
   - Нативная аутентификация TCP `AUTH`.
   - Бессерверные JWT-токены HMAC-SHA256 и проверка криптографических подписей RS256 Google OIDC JWKS.
   - Блокировка loopback (`127.0.0.1`), частных подсетей (RFC 1918), метаданных облачных провайдеров (`169.254.169.254`) и обфусцированных адресов IPv4-mapped IPv6.

## 3. Показатели производительности (Benchmarks)

Результаты нагрузочного стресс-тестирования (`benchmark.js`):

- **Пропускная способность чтения (GET)**: `820 701 ops/sec` (100k операций за 122 мс)
- **Пропускная способность записи (SET)**: `449 269 ops/sec` (100k операций за 223 мс)
- **Восстановление снимков RDB**: `100,0%` (10 503 / 10 503 ключей восстановлено)
- **Воспроизведение лога AOF**: `100,0%` (4 999 / 4 999 ключей восстановлено)
- **Удержание лимита памяти LRU**: 50 000 операций непрерывной записи удержаны в лимите 500 КБ без сбоев.

## 4. Быстрый старт (Quick Start)

```bash
# Клонирование и установка
git clone https://github.com/Ashutosh-Yadav-256/Build-Redis-In-JAVA.git
cd "Build-Redis-In-JAVA"
npm install

# Запуск (TCP 6379, Web 8080)
npm start
```

Веб-панель: откройте `http://127.0.0.1:8080`.

Запуск тестов:
```bash
npm test
# 28 сьютов, 153 теста успешно пройдены (100%)
```
