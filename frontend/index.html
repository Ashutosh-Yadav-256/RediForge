RediForge System Architecture & Engineering Whitepaper Deep-Dive

High-Level Architecture, Subsystems, Workflows & Developer Philosophy

memory WHAT IS REDIFORGE?

An enterprise-grade, memory-first key-value database engineered from the ground up to provide 100% RESP2 wire compatibility with standard Redis clients (redis-py, ioredis, Jedis) alongside an integrated real-time WebSocket observability console.

lightbulb WHY WAS IT CREATED?

Built to demonstrate first-principles systems engineering with zero external runtime dependencies in the data engine, while providing developers with a transparent, fully auditable alternative following recent Redis commercial licensing shifts.

check_circle PROBLEMS SOLVED

Delivers sub-millisecond data access, prevents accidental data erasure via dangerous command interceptors (FLUSHALL), and eliminates external sidecar complexity with unified live WebSocket telemetry.

verified Core Technical Pillars

Zero Runtime Engine Dependencies: Native standard library execution with zero external runtime packages.
Multi-Database Isolation: 16 independent logical databases (db0 – db15).
Dual Persistence Engine: Point-in-time binary RDB snapshots + Append-Only AOF write-ahead logs.
Enterprise SSRF & RBAC Guard: Loopback IP filters, IPv6 evasions blocker, and structured audit logs.

Request Execution Workflow:
1. Packet Ingestion: Raw bytes received on TCP socket or WebSocket framing buffer.
2. RESP Framing: State machine parses stream chunks into command arguments array (['SET', 'key', 'val']).
3. Security Pipeline: Command Gateway validates session authentication, RBAC privileges, and danger bounds.
4. Engine Execution: Target database executes command with $\mathcal{O}(1)$ or $\mathcal{O}(\log N)$ complexity.
5. Replication & Persistence: If mutating, command is appended to AOF stream and TTL tracked in expiry heap.
6. Encoding & Egress: Result serialized to standard RESP2 bytes and pushed to socket buffer.

RESP2 Protocol Parser Implementation

The parser in src/protocol/parser.js is written as a zero-copy state machine that processes arbitrary streaming chunks without memory leaks. It recognizes all 5 RESP2 types: Simple Strings (+), Errors (-), Integers (:), Bulk Strings ($), and Arrays (*).

save RDB Binary Snapshotting

Generates a compact point-in-time binary snapshot file (dump.rdb). Encodes database selector opcodes (0xFE), expiration timestamps (0xFD in sec, 0xFC in ms), type descriptors, length-prefixed binary strings, and EOF delimiters.

history_edu AOF Write-Ahead Logging

Logs every write command to appendonly.aof in valid RESP format. Supports configurable fsync policies (always, everysec, no) to guarantee zero data loss on crashes.

timer Dual-Phase Expiry & LRU Eviction Subsystem

1. Passive Eviction (On-Access)
When a key is requested by any read command, its expiration timestamp is evaluated against Date.now(). Expired keys are deleted immediately.
2. Active Probabilistic Cron
A timer fires every 100ms, sampling 20 volatile keys per database. If >25% are expired, the cycle repeats to prevent memory bloat.
